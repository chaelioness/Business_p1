## 4. 할 일 (순서대로)

1. **채민에게 기간 확장 요청 (막힘)**: target ≤ 2026-05-29 까지(=dev 끝). 2026-06-01 이후는 홀드아웃이라 만들지 말 것. 대략 추가 비용·호출 수 먼저 공유받기.
2. **제출 가능성 확인**: 평가(10월)에는 새 날짜의 뉴스로 피처를 다시 만들어야 함. `src/model.py` 에서 LLM 을 부를 수 있는지(과제 규칙·API 키·시간) 아니면 API 없는 대체(사전/룰)가 필요한지 팀 결정. README 에도 "API 없는 추론 구성 필요" 라고 적혀 있음. 못 쓰면 실험해도 제출에 못 넣음.
3. **확장 전 예비 실험 (fold1~3 만, 참고용으로 표시)**: 아래 4번 실험을 fold1~3 으로 먼저 돌려 코드만 준비.
4. **실험 (확장 후 fold4 주 지표, 채택 기준 그대로)** — W&B 태그 `llm_news_v6`
   - a. `v2_rsize_*` 방식: 급등락 경계를 `feature_relevant_share` 로 이동 (δ 를 train 이 고름)
   - b. **방향 게이트**: 뉴스 순방향이 갭과 반대면 급등락(0·4)을 한 칸 낮춤, 같으면 그대로 / 낮출지 말지는 train 점수로 선택. 회의의 "확실하지 않으면 급으로 안 찍기" 를 가장 직접 시험하는 형태
   - c. `v2_radd_*` 방식: s + β·(above − below)
   - d. LightGBM(B 26개) + `feature_relevant_share`, `feature_surprise_*` (결측은 결측 그대로, 0 으로 채우지 않기)
   - 결합: `symbol + target`. 우리 `run_cv` 예측의 date 열은 **대상일**임에 주의 (10/6 에 이걸로 하루 어긋난 적 있음). `cache/b_v1.parquet` 의 date 는 기준일.
5. **Reddit v4 결과가 오면** 같은 실험 틀로. 접두어 `news_`, `reddit_` 구분.
